# نادي الرجال السري (SMC) — نظام العضوية

## ⚠️ أمان أولاً — اقرأ هذا قبل أي شيء
لقد شاركتَ مفتاح `service_role` (السري) لـ Supabase في المحادثة. هذا المفتاح يتجاوز كل قواعد
الحماية (RLS) بالكامل. **لم يتم استخدامه في أي ملف من هذا الموقع** — كل الملفات تستخدم فقط
`sb_publishable_...` (المفتاح العلني). أنصحك بشدة:
1. اذهب إلى Supabase → Project Settings → API وقم بعمل **Regenerate** لمفتاح `service_role`.
2. لا تضع أي مفتاح "سري" داخل مجلد الموقع مطلقاً — أي شيء هنا يظهر للجميع.

## خطوات التشغيل

### 1) قاعدة البيانات
افتح Supabase → SQL Editor → نفّذ ملف `sql/schema.sql` كاملاً. هذا السكربت:
- يحذف أي جداول/دوال قديمة بنفس الأسماء (نظافة كاملة).
- يبني الجداول والدوال (RPC) الجديدة.
- يسجّل العضو الأول تلقائياً: **أحمد حامد المعتصم**.

**بيانات الدخول الأولى (المسؤول):**
- رمز العضوية: `SMC-000001-A-SA`
- كلمة السر المؤقتة: `SMC@Change_Me_2026`
- **غيّرها فوراً** من "تغيير كلمة السر" بعد أول تسجيل دخول.

### 2) الموقع
- رفّع كل هذا المجلد كما هو إلى مستودع GitHub، وفعّل GitHub Pages (أو اربطه بـ Vercel — كلاهما
  يعمل لأنه موقع Static بالكامل، بدون أي عملية Build).
- لا حاجة لأي إعداد إضافي — بيانات الاتصال بـ Supabase موجودة في `js/supabase-client.js`
  (المفتاح العلني فقط).

## هيكل الرمز العضوية
`SMC-NNNNNN-RANK` — الجزء الرقمي (NNNNNN) تسلسلي ودائم لكل عضو (لا يُعاد استخدامه أبداً حتى
لو حُذف عضو)، وجزء الرتبة (RANK) يتغيّر مع كل ترقية/تنزيل.

## مدة العضوية (تُحسب تلقائياً من الرتبة)
| الحالة | المدة |
|---|---|
| مسؤول / مشرف (نشط) | دائمة |
| ساموراي فقط (أول تسجيل) | سنتان، ثم تجديد سنوي |
| مسؤول سابق / مشرف سابق / عضو / أي رتبة "سابق" | سنة، تجديد سنوي |

## من يملك صلاحية تسجيل الدخول؟
فقط الرتب النشطة الآتية: `A`, `A-SA`, `A-SAF` (دخول مسؤول) — `S`, `S-SA`, `S-SAF` (دخول مشرف) —
`SA`, `A-SA`, `S-SA`, `AF-SA`, `SF-SA` (دخول ساموراي). أما الرتب "السابقة بالكامل" والعضو العادي
(`M`) فلا يملكون دخولاً، فقط بيانات محفوظة يديرها المسؤول.

## تنسيق الشهادات والبطاقة (مهم)
الرمز في `js/certgen.js` يكتب البيانات فوق الصور التي أرسلتها (`assets/cert_register_template.jpg`,
`cert_rank_template.jpg`, `card_template.jpg`) باستخدام `<canvas>` في المتصفح — بدون أي رفع
لملفات جديدة كل مرة.

**إحداثيات الكتابة قُدّرت بشبكة قياس دقيقة على صورك الأصلية**، لكنها Best-effort. بعد أول شهادة
تُنزّلها، افحصها: إن احتاج أي حقل تعديلاً بسيطاً في موضعه، عدّل الأرقام `x` / `y` في `COORDS`
داخل `js/certgen.js` — كل حقل معلّق باسمه بوضوح.

## ما لم يُبنَ (خارج نطاق هذا التسليم الأول)
- شاشة "تسجيل عضو جديد" لا تُنشئ حساب Supabase Auth حقيقي — النظام كله يعمل بجلسات خاصة به
  (RPC + جدول `sessions`) لأن الموقع Static بالكامل بدون سيرفر خاص به. هذا كافٍ وآمن للاستخدام
  المطلوب، لكنه ليس نظام مصادقة Supabase Auth القياسي.
- تصدير الشهادة/البطاقة بصيغة PDF غير مطلوب هنا صراحة (المطلوب JPG) — تم تنفيذه بصيغة JPG فقط
  كما طُلب.
